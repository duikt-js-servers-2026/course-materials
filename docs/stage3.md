## 1. Модуль `src/fetcher.js` - завантаження JSON

CommonJS (`module.exports`). Для HTTP-запитів використовуйте вбудований `fetch` (Node.js 20+), сторонні пакети не потрібні.

**`fetchJson(url, { timeout = 2000, retries = 0 } = {})`** - завантажує JSON за адресою й повертає розібраний об’єкт.
- Якщо сервер не відповів за `timeout` мс - запит перериваємо (`AbortSignal.timeout`) і кидаємо помилку, повідомлення якої містить слово `timeout`.
- Відповідь із кодом 4xx - помилка з повідомленням `HTTP <код>` (наприклад, `HTTP 404`), **без повторів**.
- Відповідь із кодом 5xx, тайм-аут або мережева помилка - **повторити** запит, але не більше ніж `retries` разів. Якщо всі спроби невдалі - кинути помилку останньої спроби (`HTTP 503`, `timeout ...`).
- Тіло відповіді - не JSON - помилка без повторів.

**`loadAll(urls, { mode = 'parallel', timeout, retries } = {})`** - завантажує кілька адрес і **ніколи не кидає помилку**. Повертає масив у тому самому порядку, що й `urls`:
- `{ url, ok: true, data }` - якщо вдалося;
- `{ url, ok: false, error }` - якщо ні (`error` - рядок, повідомлення помилки).

Режими:
- `parallel` - усі запити одночасно (`Promise.all` / `Promise.allSettled`), загальний час ≈ час найдовшого запиту;
- `sequential` - наступний запит починається лише після завершення попереднього, загальний час ≈ сума.

Тести перевіряють режими **за часом виконання**, тож «паралельний» режим, який насправді йде по черзі, не пройде.

## 2. Модуль `src/logstats.js` - великий файл журналу

**`analyzeLog(file)`** - повертає проміс зі статистикою файлу журналу. Кожен рядок має формат:

```
2026-10-01T10:00:00.000Z ERROR db timeout
<час>                    <рівень> <повідомлення>
```

Рівень - `INFO`, `WARN` або `ERROR`. Порожні рядки пропускаються, рядки іншого формату рахуються як некоректні.

Результат:

```json
{
  "lines": 60000,
  "invalid": 1,
  "levels": { "INFO": 36000, "WARN": 18000, "ERROR": 6000 },
  "first": "2026-10-01T00:00:00.000Z",
  "last": "2026-10-01T16:39:59.000Z",
  "topErrors": [
    { "message": "db timeout", "count": 2400 },
    { "message": "auth failed", "count": 1200 },
    { "message": "disk full", "count": 1200 }
  ]
}
```

- `lines` - кількість коректних рядків, `invalid` - некоректних;
- `levels` - кількість за рівнями (усі три ключі є завжди);
- `first` / `last` - час першого й останнього коректного рядка (`null`, якщо таких немає);
- `topErrors` - до 3 найчастіших повідомлень рівня `ERROR`: за спаданням кількості, за однакової кількості - за алфавітом.

**Головна вимога:** файл читається **потоком** - `fs.createReadStream` + `readline` (або обробка `data`-подій), а не цілком у пам’ять. Тести забороняють `fs.readFile` / `fs.readFileSync` під час виклику `analyzeLog`.

Якщо файл не існує - проміс відхиляється.

## 3. Утиліта `collect`

```
node src/collect.js fetch [--sequential] [--timeout мс] [--retries n] <url> [<url> ...]
node src/collect.js log <файл>
```

- `fetch` - виводить у **stdout** результат `loadAll` як JSON (`JSON.stringify(result, null, 2)`). Режим за замовчуванням - паралельний; `--sequential` вмикає послідовний.
- `log` - виводить у stdout результат `analyzeLog` як JSON.

Приклад:
```bash
node src/collect.js fetch --timeout 1000 --retries 2 https://jsonplaceholder.typicode.com/todos/1 https://jsonplaceholder.typicode.com/todos/2
node src/collect.js log logs/app.log
```

### Помилки та коди виходу

Повідомлення про помилку - у **stderr**, починається з `Error:`; stdout порожній. Виняток - код 5: там результати все одно виводяться в stdout.

| Ситуація | Код |
|---|---|
| успіх | `0` |
| немає команди, невідома команда, невідома опція | `1` |
| `fetch` без жодної адреси, `log` без файлу, опція без значення | `2` |
| некоректне значення `--timeout` (ціле ≥ 1) або `--retries` (ціле ≥ 0) | `3` |
| файл журналу не існує | `4` |
| `fetch`: хоча б один запит невдалий (результати при цьому виведено) | `5` |
