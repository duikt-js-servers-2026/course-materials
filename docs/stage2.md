# Етап 2. Обробка набору даних із JSON

Дисципліна «JavaScript у створенні серверів» · наскрізний проєкт · **етап 2 з 6** (лабораторні 3–5, захист на лаб. 5, 5 балів)

Етап виконується **у тому самому репозиторії**, що й етап 1. Утиліта `calc` з етапу 1 залишається, її тести мають і далі проходити.

## 1. Предметна область і дані

Оберіть предметну область свого варіанта (наприклад, книгарня, кінотеатр, магазин електроніки, бібліотека настільних ігор) і створіть файл **`data/items.json`** — масив щонайменше з **20** записів такої структури:

| Поле | Тип | Опис |
|---|---|---|
| `id` | ціле > 0, унікальне | ідентифікатор |
| `title` | непорожній рядок | назва |
| `category` | непорожній рядок | категорія (щонайменше 3 різні на весь набір) |
| `price` | число ≥ 0 | ціна |
| `quantity` | ціле ≥ 0 | кількість |
| `date` | рядок `РРРР-ММ-ДД` | дата (надходження, випуску тощо) |

Назви полів однакові для всіх варіантів — від предметної області залежить лише зміст.

## 2. Модулі

Код розділіть на три модулі (CommonJS, `module.exports` / `require`):

**`src/data.js`**
- `loadItems(file)` — читає JSON-файл і повертає масив записів. Кидає помилку, якщо файл не існує, містить некоректний JSON або в ньому не масив.

**`src/query.js`** — чисті функції, які **не змінюють** вхідний масив:
- `filterItems(items, { category, minPrice, maxPrice })` — записи, що відповідають усім заданим умовам (незадані умови ігноруються; межі цін включні).
- `groupCount(items, field)` — об’єкт «значення → кількість записів»; `field` — `category` або `year` (рік із поля `date`).
- `stats(items)` — об’єкт `{ count, totalQuantity, totalValue, avgPrice, minPrice, maxPrice }`, де `totalValue` — сума `price × quantity`, `avgPrice` — середня ціна; `totalValue` і `avgPrice` округлюються до 2 знаків. Для порожнього масиву: `{ count: 0, totalQuantity: 0, totalValue: 0, avgPrice: 0, minPrice: null, maxPrice: null }`.
- `topN(items, n, field = 'price')` — `n` записів із найбільшим значенням `field` (`price` або `quantity`); за однакових значень — у порядку зростання `id`.

**`src/report.js`** — консольна утиліта, яка підключає `./data` і `./query`.

## 3. Утиліта `report`

```
node src/report.js <команда> [опції]
```

Результат виводиться в **stdout** у форматі **JSON** (`JSON.stringify(result, null, 2)`).

| Команда | Опції | Результат |
|---|---|---|
| `list` | `--category`, `--min-price`, `--max-price` | масив записів після фільтрації |
| `group` | `--by category\|year` (обов’язкова) | результат `groupCount` |
| `stats` | `--category` | результат `stats` для відфільтрованих записів |
| `top` | `--n N` (обов’язкова), `--by price\|quantity` (за замовчуванням `price`) | результат `topN` |

Усі команди приймають `--file шлях` — файл даних; без нього використовується `data/items.json` вашого проєкту.

Приклади:
```bash
node src/report.js list --category Поезія --max-price 300
node src/report.js group --by year
node src/report.js top --n 5 --by quantity
```

### Помилки та коди виходу

Повідомлення виводиться в **stderr** і починається з `Error:`; stdout порожній.

| Ситуація | Код |
|---|---|
| успіх | `0` |
| немає команди, невідома команда, невідома опція | `1` |
| не вказано обов’язкову опцію (`--by` для `group`, `--n` для `top`) | `2` |
| некоректне значення опції (не число, `--n` < 1, недопустиме `--by`) | `3` |
| файл даних не існує, некоректний JSON або не масив | `4` |
