# Етап 5. REST API з базою даних SQLite

Дисципліна «JavaScript у створенні серверів» · наскрізний проєкт · **етап 5 з 6** (5 балів; захищається на заліку)

Етап виконується **у тому самому репозиторії**. Попередні етапи й тести мають і далі проходити.

Тепер дані не лише читаються, а й створюються, змінюються й видаляються - і зберігаються в базі даних. Використовуємо **SQLite** через вбудований модуль Node.js `node:sqlite`: нічого не треба встановлювати, база - це один файл.

## 0. Підготовка

```bash
git fetch course
git checkout course/main -- docs/stage5.md test/stage5.test.js
git commit -m "Етап 5: умова та тести"
```

Потрібен Node.js **22.13 або новіший** (`node -v`). Файли бази даних (`*.db`) додайте в `.gitignore`.

Модуль `node:sqlite` поки позначений як експериментальний і друкує попередження `ExperimentalWarning` - це нормально.

```js
const { DatabaseSync } = require('node:sqlite');
const db = new DatabaseSync('data/app.db');
db.prepare('INSERT INTO categories (name) VALUES (?)').run('Поезія');
db.prepare('SELECT * FROM categories WHERE id = ?').get(1);
```

Завжди використовуйте параметри `?` у запитах, а не підставляйте значення в текст SQL - інакше це SQL-ін’єкція.

## 1. Ресурси

Два пов’язані ресурси: **категорії** і **товари** (кожен товар належить категорії).

| Ресурс | Поля |
|---|---|
| категорія | `id` (ціле, автоматично), `name` (рядок 1-50 символів, унікальний) |
| товар | `id` (ціле, автоматично), `title` (рядок 1-100), `categoryId` (id наявної категорії), `price` (число ≥ 0), `quantity` (ціле ≥ 0), `date` (дата `РРРР-ММ-ДД`) |

Таблиці створюються при старті, якщо їх ще немає (`CREATE TABLE IF NOT EXISTS`) - це найпростіша міграція.

## 2. Модуль `src/rest.js`

```js
module.exports = { createRestApp };
// createRestApp({ dbFile }) -> Express-застосунок без listen
```

`dbFile` - шлях до файлу бази даних, за замовчуванням - зі змінної середовища `DB_FILE` або `data/app.db`. Тести передають власний тимчасовий файл.

Рекомендована структура: підключення й міграції - в окремому `src/db.js`, маршрути - у `src/rest.js` (або розбийте на роутери).

## 3. Маршрути

### Категорії

| Запит | Успіх | Помилки |
|---|---|---|
| `GET /api/categories` | `200` масив за зростанням `id` | |
| `POST /api/categories` `{ name }` | `201` створена категорія, заголовок `Location: /api/categories/<id>` | `400` валідація, `409` така назва вже є |
| `GET /api/categories/:id` | `200` | `404`, `400` (id - не ціле додатне) |
| `GET /api/categories/:id/products` | `200` товари категорії | `404` |
| `PATCH /api/categories/:id` `{ name }` | `200` оновлена | `400`, `404`, `409` |
| `DELETE /api/categories/:id` | `204` | `404`, `409` якщо в категорії є товари |

### Товари

| Запит | Успіх | Помилки |
|---|---|---|
| `GET /api/products` | `200` масив + заголовок `X-Total-Count` | `400` некоректні параметри |
| `POST /api/products` (усі поля) | `201` + `Location: /api/products/<id>` | `400` |
| `GET /api/products/:id` | `200` | `404`, `400` |
| `PUT /api/products/:id` (усі поля, повна заміна) | `200` оновлений товар | `400`, `404` |
| `PATCH /api/products/:id` (лише ті поля, що змінюються) | `200` оновлений товар | `400`, `404` |
| `DELETE /api/products/:id` | `204` | `404` |

Параметри `GET /api/products`:
- `categoryId`, `minPrice`, `maxPrice` - фільтри (межі включні);
- `sort` - `id` (за замовчуванням), `price`, `-price`, `title`, `-title` (мінус - за спаданням; за однакових значень - за `id`);
- `limit` (ціле 1-100, за замовчуванням 50) і `offset` (ціле ≥ 0, за замовчуванням 0) - пагінація;
- `X-Total-Count` - скільки всього товарів відповідає фільтрам, **без урахування** `limit`/`offset`.

## 4. Помилки

- Усі помилки - JSON `{ "error": "опис" }`.
- Помилки валідації - `400` з масивом `details`, по одному елементу на **кожне** некоректне поле: `{ "error": "validation failed", "details": [{ "field": "price", "message": "number >= 0" }] }`. Неіснуюча категорія у `categoryId` - теж `400` з `field: "categoryId"`.
- Некоректний JSON у тілі запиту - `400`.
- Невідомий маршрут - `404`.
- **Централізована обробка помилок**: маршрути кидають помилки (`throw`), а одна middleware `(err, req, res, next)` перетворює їх на відповідь. Невідомі помилки - `500` `{ "error": "Internal server error" }` без деталей (деталі - лише в журнал сервера).

## 5. Запуск

```js
if (require.main === module) {
  const port = Number(process.env.PORT) || 3000;
  createRestApp().listen(port, () => console.log(`http://localhost:${port}/api`));
}
```

Додайте в `package.json` скрипт, наприклад `"api": "node src/rest.js"`.
